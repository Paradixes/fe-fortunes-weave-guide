# fe-fortunes-weave-guide

静态中文攻略与偏好驱动的培养规划。攻略资料存于 SQLite；Ubuntu 上由只读服务提供数据，Sites 使用同库导出的静态资料。用户偏好和收集库存仅保存在浏览器本地。


## 本地运行

这是无需安装前端依赖的 HTML / CSS / JavaScript 项目。需要 Python 3；修改攻略数据或执行 JavaScript 校验还需要 Node.js。

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory dist
```

打开 http://127.0.0.1:8765/ 。页面直接读取同库导出的静态资料，本地浏览不需要部署后端。

更新 SQLite 数据后生成网页数据：

```bash
node scripts/build-abilities.cjs /tmp/fe-guide-catalog.json
python3 scripts/catalog-db.py import --source /tmp/fe-guide-catalog.json
node scripts/build-catalog.cjs
```

常用验证：

```bash
node scripts/verify-site.cjs
node scripts/verify-workbench.cjs
node scripts/verify-cultivation.cjs
python3 scripts/verify-sqlite.py
python3 scripts/check-public-export.py
```

可选的只读 SQLite API：

```bash
python3 server/catalog_server.py --db data/catalog.sqlite3 --port 18776
```

服务器配置均为通用示例；部署时填写自己的域名和路径。请勿提交密钥、环境变量、本机状态或真实服务器地址。

## 数据修改

唯一数据源是 `data/catalog.sqlite3`；`data/catalog.json` 是构建生成的交换快照。角色、职业、装备及来源、招募记录、事件、斗技场项目、骑宠、地图、培养规划和熟练说明集中在这里。`planning` 保存每名角色的整合方案和实际可培养路线，所有界面使用同一组读取函数。主副职选择理由由共用规则根据这些记录生成。不同路线的推荐允许不同，但同一方案不再由页面脚本覆盖修改。

运行 `node scripts/build-catalog.cjs` 从 SQLite 读取并校验后生成 `dist/catalog.js`、`roster.json`、`learning.json` 和 `map.json`。生成文件请勿单独编辑。完整技能与地图仍按需载入；其内容来自同一目录，并非另外维护的数据源。运行时数据目录冻结，防止某个界面意外修改其他界面的资料。

校验检查角色 / 职业 / 装备 ID、路线实际可招募性、方案职业引用、主职与解释记录一致性、同阶段主副职去重、事件和阵容引用。编译失败时停止发布；资料准确性仍需人工核对游戏或资料来源。

## 界面

`dist/app.js`、`v9.js`、`reasons.js` 负责共享查询、偏好计算与展示。`locale.js` 处理中文名称。地图仅为已有地点记录提供入口，无已收录地点的装备不显示地图按钮。浏览器库存不会因切换方案或来源被扣除。

静态网页位于 `dist/`，可部署到任意静态服务器；`server/` 提供可选的只读 SQLite 数据接口。

## 验证

运行 `node scripts/verify-site.cjs`。无界面的回归覆盖全局页面隔离、各路线角色档案、职业 / 装备弹窗、库存计算、真实地图入口、主副职理由与统一方案读取。该检查不替代真实浏览器的布局观察。

## 来源库与图片标签

装备库目前收录147项，基础武器与后期首领掉落均使用同一装备目录和弹窗。观战记录区分明确日期、章首剧情和待核实日期，路线日历与斗技场页面复用同一事件组件。资料仍有缺口，未核实的来源、材料采集点及日程在对应字段注明。

技能图片由共享目录生成索引：技能类别与武器战技复用现有游戏内图标，没有独立图标的个人技能使用角色头像。装饰仅处理文本节点，保留属性和链接；已有图片不重复添加。

## 跨线投入规则

`crossRoutePolicy` 保存早期力量、负重门槛、后备补防与战技 / 特技融合说明。补力量可沿剑术D→C→B取得斗士、土匪、勇士；不把剑客当力量成长职业。后备补属性需要在指定职业实际升级，宿屋「实战」与只加职业 / 技能经验的「训练」分开说明。每名角色的具体分支仍放在 `planning`，不强制给所有角色分配相同补修。中文搜索在 composition 结束后提交，输入期间保留原节点与结果。

## 章节日历

任务与观战复用 `events`，主线关键时间点与游戏星期锚点放在 `chapterCalendar`。按章切换，月历条带展示受理区间、观战时间、截止日期和主线推进点；点击展开详情。只有章节的记录单独展示，不伪造具体日期。蕾达第五章已确认有观战，准确日期与时段仍待核实。角色卡片个人技能不重复附头像，角色概要不装饰技能图标；斗技场两个维度都复用角色肖像。

## 熟练奖励与行内图片

`masterySkills` 按技能名保存熟练奖励类型、效果与来源，覆盖60个职业；兼容旧接口的 `masteryNotes` 由编译器派生。职业库、职业路线及资料弹窗复用 `masteryFact`，不单独手填说明。尚未明确的要塞减伤数值不作猜测。开局职责覆盖复用紧凑角色组件；行内技能标签两侧保留等距间隔，图片按文字字号缩放并与文字居中，标签整体沿正文基线对齐。

## 月份日历

日历改为月份筛选，不再以章节裁切事件；跨月任务在相关月份均显示且保留原章节范围，截止日期可独立落在下一月。`chapterCalendar.mainline` 区分主线准备开始与结束，蕾达第10、12章开始日期有明确来源，其余开始日按已知结束日期、回合数与每天4回合推算，并在标记与详情中注明。剧情转场空档不纳入准备期。斗技场角色副标题读取统一的 `skillTargets`，项目列不重复列技能。

## 开局头像组

职责覆盖与开局成员表使用 `stackedCharacters`：圆形头像负间距叠放，旁边一组可点击姓名；头像和姓名均可打开档案，键盘焦点会抬起当前头像。第三部没有事件与主线日程记录时，同时移除日历章节与导航入口。

## 简化主线区间

主线不再生成独立起止点，只显示一条准备区间。跨周续带保留颜色与点击，文字每月只出现一次；日期依据继续保存在目录元数据，不在月历中重复说明。修正区间按钮的 `main` 类与全站主内容左边距冲突，保证条带与日期列对齐。

角色图鉴支持独立的主养路线筛选，使用统一规划数据的 primaryRoutes；多线互补角色可同时匹配多个主养路线，第三部加入按 firstPart 区分。可与职业方向、评级及搜索组合，不改变路线攻略的当前路线。数量紧邻搜索，评级说明紧邻评级筛选。

首页和路线封面共用 catalog.presentation 的主角信息；立绘使用任天堂官方图片地址（加载失败回退本站头像），主题短句为本站文案。装备卡片由统一装备 effect 提取数字指标，完整资料仍在详情弹窗；标题类别图标沿用游戏技能素材。

## SQLite 与 Ubuntu 数据服务

`entities` 按集合、稳定 ID 与顺序存角色、职业、装备、事件、地点、技能和方案；`sections` 存其余目录配置；`bundles` 存校验后生成的数据响应。启动 `python3 server/catalog_server.py --db data/catalog.sqlite3`，服务仅监听 `127.0.0.1:18776`，数据库以只读连接打开。Nginx 代理 `/catalog.js`、`/roster.json`、`/learning.json`、`/map.json` 与 `/api/`，其余图片和界面仍直接静态服务。

查看运行状态：`GET /api/health`。个人库存与偏好不发送到服务器，继续使用原 localStorage 键名。生产数据库及服务代码位于 `/var/www/fire-emblem/app-current`，systemd 服务为 `fire-emblem-catalog.service`。

需要从交换 JSON 导入资料时先备份数据库，再执行 `python3 scripts/catalog-db.py import --source <file>`，然后 `node scripts/build-catalog.cjs`。构建会重新导出 JSON 快照和静态 bundle，并更新库内响应缓存。修改 SQLite 后必须重新构建以更新客户端数据。`python3 scripts/verify-sqlite.py` 检查无损交换、完整性、只读连接、HTTP 响应与条件缓存。
